Solver_2D: a Navier-Stokes solver built with an AI agent

Personal project, May 2026 – present · github.com/adiikumar/Solver_2D

A 2D incompressible Navier-Stokes solver on a staggered MAC grid, built explicitly to study whether a coding agent can be trusted with numerics. CFD is near worst-case for this: a sign error compiles, runs, and draws a plausible contour. Correctness is long-range consistency across files, not local syntax. The codebase is small enough that "I reviewed every line" is literally true.

FormulationPrimitive variables, staggered MAC grid, RK3 fractional step (Le & Moin, JCP 1991)
Pressure PoissonFFT with modified wavenumbers (periodic) · unpreconditioned CG (wall-bounded)
Discrete structureGradient built as minus the divergence transpose → projection removes divergence exactly
SimplificationProjection applied at every RK3 substage (a documented simplification, not a silent one)
WorkflowSpec → generate → review → run, human-gated. No MCP or autonomous execution: Claude (Anthropic) as conversational pair programmer
15/15unit tests passing, run locally

Caught wrong, on purpose: a hand-rolled divergence diagnostic used backward differences against the solver's forward-difference convention. It confidently flagged a correct solution as divergent. The test suite stayed green because the diagnostic sat outside the tested operator suite. Standing rule since: diagnostics are code, reviewed like code, and must call the solver's own tested operators.

Conjugate heat transfer design study: liquid-cooled cold plate

Personal project, Apr 2026 – Aug 2026

A 96-case conjugate heat transfer design sweep of a liquid-cooled microchannel cold plate under a 700 W GPU-class heat load, automated end to end with a templated SLURM array pipeline on a university HPC cluster. A Gaussian Process surrogate trained on the converged sweep then drove a constrained grid-search optimization over the design space.

Screw compressor: thermodynamic model and surrogate

Research co-op, Kirloskar Pneumatic

A chamber-volume thermodynamic model of a twin-screw compressor with six leakage paths integrated against CoolProp. The no-leakage base case overpredicted mass flow by ~66 g/cycle versus vendor software. That gap motivated adding the leakage terms. A POD-reduced Gaussian Process surrogate then maps rotor geometry to the compressed chamber-cycle response.

DomainSingle working chamber vs. rotor crank angle (0–360°): lumped thermodynamic model, not 3D CFD
Training data1,000 runs × 700 crank-angle steps per run, forming the POD snapshot matrix
Dimensionality reductionTruncated SVD (POD): 3 to 8 modes typically capture ~99% of variance
SurrogateGaussian Process, Matérn kernel (ν=2.5) plus a white-noise kernel for solver noise
InputsL/D ratio, wrap angle, lobe combination, rotor speed, with a scaler fit on the training split only

GPU-accelerated DNS: pressure-Poisson solver port

Research Assistant, Computational Fluid Mechanics Lab, UW

Working inside the lab's flagship DNS solver for droplet-laden turbulent flows: C/CUDA kernels with Fortran host wrappers and MPI on the Hyak cluster. Focused on the critical pressure-Poisson solver: optimizing it on NVIDIA architectures, then porting the CUDA implementation to AMD GPUs via HIP and hipFFT, verified against Taylor-Green vortex regressions.

CodebaseC/CUDA kernels, Fortran host wrappers, MPI, run on the UW Hyak cluster
TargetPressure-Poisson solver, performance optimization on NVIDIA architectures
PortCUDA → AMD GPU via HIP + hipFFT
VerificationLab's ptest framework: random right-hand sides, no special structure, identities that must hold for any input. Taylor-Green vortex regression gates every change
